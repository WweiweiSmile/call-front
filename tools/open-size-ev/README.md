# 翻前开池尺度对比模拟

回答一个问题：**翻前开池 7BB 和开池 10BB，在一千手里哪个收益更高？**

这个工具不属于小程序本体，是离线跑的分析脚本。放在 `tools/` 下是为了不被打包进小程序产物
（根 `tsconfig.json` 的 `include` 只有 `./src` 和 `./types`）。

## 怎么跑

```bash
pnpm sim:opensize
```

等价于：

```bash
node_modules/.bin/tsc -p tools/open-size-ev/tsconfig.json && node tools/open-size-ev/dist/index.js
```

跑一次约十几秒，输出一份完整的报告。要改参数就加 `--key=value`：

```bash
# 换筹码深度、加抽水
node tools/open-size-ev/dist/index.js --stack=200 --rake=0.05 --rake-cap=3

# 带前注的局：9 人桌每人 0.5，盲注+前注合计 6bb
node tools/open-size-ev/dist/index.js --ante=0.5

# 改范围和诈唬频率，按 1 万手一局统计
node tools/open-size-ev/dist/index.js \
  --ante=0.5 --rangeA=0.35 --airA=0.10 --rangeB=0.25 --airB=0.35 \
  --hands=10000 --blocks=800 --sensitivity-blocks=60

# 只跑主对比，跳过敏感性扫描（快很多）
node tools/open-size-ev/dist/index.js --sensitivity=0

# 换对手模型
node tools/open-size-ev/dist/index.js --threebet=0.03 --float=0.2 --stab=0.5

# 只跑自检
node tools/open-size-ev/dist/index.js --selftest=1 --brute=200000 --blocks=1 --hands=1
```

## 默认场景

| 项 | 值 |
| --- | --- |
| 牌桌 | 9 人桌，我在 BTN |
| 筹码 | 100bb，盲注 0.5-1，无前注，无抽水（死钱 1.5bb） |
| 开池 7BB 一方 | 范围 40%、纯诈唬 10%、目标 2.5 名跟注者 |
| 开池 10BB 一方 | 范围 22%、纯诈唬 35%、目标 1.5 名跟注者 |
| 样本 | 每策略 40 万手 = 400 组 × 1000 手 |

`--ante=0.5` 时死钱变成 6bb（小盲 0.5 + 大盲 1 + 前注 0.5×9），报告头部会把这笔账拆开印出来。

**"3-4 人底池"按含我在内的总人数理解**，所以 7BB 配 2.5 名跟注者、10BB 配 1.5 名。
如果你说的其实是"3-4 个跟注者"，改 `--callersA=3.5 --callersB=2.5` 即可。

## 常用参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--hands` | 1000 | 每局手数。问"1 万手下哪个好"就传 10000 |
| `--blocks` | 400 | 局数。总手数 = hands × blocks，精度只看总手数 |
| `--sensitivity-blocks` | 400 | 扫描与分解每档的局数 |
| `--ante` | 0 | 每名玩家的前注。0.5 → 9 人桌死钱 6bb |
| `--stack` / `--sb` / `--bb` | 100 / 0.5 / 1 | 筹码与盲注 |
| `--rake` / `--rake-cap` | 0 / 0 | 抽水比例与上限 |
| `--rangeA` / `--airA` | 0.40 / 0.10 | 7bb 一方的开池范围与纯诈唬频率 |
| `--rangeB` / `--airB` | 0.22 / 0.35 | 10bb 一方的开池范围与纯诈唬频率 |
| `--callersA` / `--callersB` | 2.5 / 1.5 | 目标跟注人数（不含我） |
| `--threebet` / `--float` / `--stab` | 0.01 / 0.12 / 0.35 | 对手模型 |
| `--sensitivity` / `--selftest` | 1 / 1 | 传 0 跳过 |
| `--brute` | 20000 | 对拍枚举的组数 |

## 结论怎么读

报告里最后那节「1000 手一局的结果分布」才是答案，两个数必须一起看：

- **平均差值**：两条策略逐局相减再平均，因为吃的是同一批发牌，发牌运气被消掉了。
- **95% 区间**：跨过 0 就说明这次比较分不出高下。

一个 1000 手的 block 本身标准差有上千 bb，所以单看某一局谁赢毫无意义 ——
这也是为什么报告里既给平均也给「运气差的 5% / 运气好的 95%」。

## 模型长什么样

一手牌的流程：

1. **翻前**：我按开池范围决定开不开。开池后逐个掷骰子决定每个对手 3-bet / 跟注 / 弃牌。
2. **没人跟**：收下盲注，这手结束。
3. **进翻牌**：发三张，我给自己的牌打分（成手牌型 + 听牌），按分数落进三档之一决定下注还是过牌。
   - 成牌档 → 下注概率高
   - 听牌档 → 半诈唬
   - **完全没中档 → 下注概率就是那个"纯诈唬频率"** —— 你说的"没中牌丢不丢"调的就是它
4. **对手应对**：按自己的牌力与底池赔率决定跟或弃。下注越大、街越靠后，跟注门槛越高。
5. **我过牌**：对手有一定概率主动下注，我跟不动就弃。跟不动也可以飘一手。
6. **摊牌**：比七张牌里最好的五张。

## 关键假设与已知偏差

结论依赖下面这些简化。**前两条是结构性的，会实质影响数值**，其余影响较小。

1. **跟注范围用的是冷胜率排序，会低估投机牌。**
   小对子、同花连张这类牌在"对随机手的胜率"排序里位置偏低，但现实中恰恰是它们最常跟注。
   后果是：模型里"跟注人数变多"等于"对手的牌明显变弱"，这个效应被放大了。
   所以报告里"跟注人数 × 两种策略"那张表，行方向的解读要谨慎，**列方向的比较不受影响**。

2. **翻后对手只会跟注或弃牌，不会加注。**
   我拿不到被加注时的信息，底池也不会失控。这让"我下注"比现实中安全。

3. 我过牌后最多一名对手下注，其余人弃牌。
4. 遇到 3-bet 我用开池范围最强的一段去跟，跟注后翻牌先过牌（我是跟注方）。
   直接弃牌时按开池额计入损失，**开池越大损失越多 —— 这一项偏袒小尺度开池**，
   所以 10BB 的领先是在逆风下取得的。
5. `power`（手牌强度分）是手调的启发式，不是标定过的胜率。
   所有常数集中在 `strategy.ts` 顶部，想试别的打法改那一处就够。
6. 位置只体现在"翻牌没人下注时我先说话"和"跟 3-bet 后我不先开枪"。
7. **跟注人数是钉死的，不随死钱变化。**
   死钱涨到 6bb 时，跟注的底池赔率从 1.21:1 变成 1.86:1，现实中对手会明显跟得更宽，
   于是两套打法都会遇到更多人跟注 —— 这对本来就跟注更多的 7bb 更不利。
   本模型按 `--callersA/B` 固定人数，**低估了死钱变大对 7bb 的伤害**。

## 自检

每次运行前会先跑一遍自检，`--selftest=0` 可跳过。五项里最重要的是**对拍暴力枚举**：
从七张里枚举全部 21 种五张组合，逐一评估取最大值，和评估器一把梭的结果比。
跑 20 万组随机七张，两者必须完全相等。

这项不是形式。写这个工具的过程中它抓到过两个真 bug：

- **两对的踢脚取错**：`KK 99 22 7` 这类三对牌面，最优五张是 `KK+99+7`，
  踢脚该是 7，但按"张数优先"排序后紧跟着的是第三对的 2。
- **四条的踢脚取错**：同一类错误，`4444 + 22 + 7` 的踢脚该是 7 而不是 2。

另一项是**对称性不变量**：把 169 种起手牌的对随机手胜率按组合数加权平均，
必须精确等于 50%（我和对手在发牌上完全平权）。任何采样偏差都会把它推开。
这条比"某个具体牌值等于多少"可靠 —— 它不依赖任何外部表格。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.ts` | 命令行入口、参数解析、编排 |
| `evaluator.ts` | 七张牌评估器（纯函数，输出可比较的整数分值） |
| `range.ts` | 169 种起手牌、胜率表、范围截断与抽样 |
| `strategy.ts` | 手牌打分与下注/跟注规则，**所有可调常数在这里** |
| `sim.ts` | 模拟引擎 |
| `report.ts` | 输出排版 |
| `selftest.ts` | 自检 |
| `rng.ts` | 可复现的洗牌 |
| `node-shims.d.ts` | node 全局变量的最小声明（仓库没装 `@types/node`） |

## 为什么不用现成的库

仓库里没有任何手牌评估代码（`src/utils/cards.ts` 只做牌串解析和校验），
而为一个离线分析脚本引入 `pokersolver` 之类的依赖，会让小程序的依赖树多一份用不到的东西。
评估器本身不到 150 行，且有暴力枚举对拍兜底，自己写更可控。
