# 翻前全下决策器（静态网页）

回答一个问题：**4 人桌、8BB 等筹码，翻前我拿这手牌，面对前面几个人的全下，该推还是该弃？**

打开 `index.html` 就能用 —— 单文件、零依赖、不联网（策略表内嵌在 HTML 里，
所以在 `file://` 下双击也能跑，不受浏览器读本地文件的限制）。
**整页一屏放得下，不滚动**：手牌网格的边长 = `min(可用宽, 可用高)`，
用 `ResizeObserver` 盯着可用空间变化（对手区出现/消失会改变高度），所以手机上也不会滚。

## 怎么用

1. 选我的手牌 —— 就是那块 13×13 的网格（右上区同花、左下区非同花），
   它**同时是范围图**：色块越绿 = 这个局面里这手牌越该全下，所以不用另外看一张表
2. 选我的位置（UTG / BTN / SB / BB，就是翻前的行动顺序）
3. 对手区会列出**比我早行动的位置**，勾上谁 = 谁已经全下
4. 结论区给出这手牌的全下频率：
   - 100% 全下 / 100% 弃牌 → 纯策略，直接给答案
   - 0%~100% 之间 → 混合策略，**选完就自动按这个概率掷一次随机数**（不用点按钮），
     想再看几次分布就点「再掷一次」，下方会累计「已掷 N 次：跟注 x 次（y%）」

比我在 BB 且前面都弃牌时没有决策（直接收盲注），页面会直接说明。
模型假设、数值稳定性的含义都收在右上角「模型说明」浮层里，主屏不放长文。

## 数据从哪来

`tools/open-size-ev/allin-nash.ts` —— 同一目录下的 4 人 push/fold 纳什均衡求解器
（每轮 2000 组发牌 × 600 轮虚构对局，线性平均）。本页只是它的策略表的前端。

重新生成策略表（两次，第二次只用来算数值稳定性）：

```bash
node_modules/.bin/tsc -p tools/open-size-ev/tsconfig.json
node tools/open-size-ev/dist/allin-nash.js --json=1 --avg=linear --iters=600 --deals=2000 --seed=1 > tools/allin-chart/strategy-8bb.json
node tools/open-size-ev/dist/allin-nash.js --json=1 --avg=linear --iters=600 --deals=2000 --seed=3 > tools/allin-chart/strategy-8bb.seed3.json
node tools/allin-chart/build.js          # 把策略表内嵌进 index.html
```

改界面只动 `page.template.html`，改完重跑 `build.js`。`build.js` 会先校验
（169 个手牌类、14 个决策节点、概率都在 [0,1]），不合法直接构建失败，
免得把一份缺节点的表发到网页上。

`--avg` 是历史平均的权重方式，`fp` 是求解器原来的调和平均，`linear` 是越晚的轮次
权重越大。同一节点上（BTN 开池）「该弃的牌却有小概率」的牌类数：调和 76 个 → 线性 25 个。
线性平均是现在发货用的。

## 自检

```bash
node tools/allin-chart/selftest.js
```

页面是原生 JS、没有测试运行器，所以自检用最小 DOM 打桩把 `index.html` 里的脚本
直接跑在 node 上，断言 42 项：13×13 网格与策略表的 key 集合是否完全一致（同花/非同花
方向最容易写反）、每个合法局面是否都能查到节点、换位置/勾对手/换手牌后文案是否跟着变、
**混合牌不点任何按钮就自动出结果**、纯策略不出现掷骰入口、**掷骰函数是否真的按 p
分布出结果**（4000 次看经验频率）、色块透明度是否等于 `0.08 + 0.92×p`、
网格尺寸是否跟着可用空间走（一屏不滚动的前提）。

## 数值可信度

均衡边界附近的牌本来就是混合的，边界在哪会随随机种子小幅移动。页面每个局面都印了
「数值稳定性 ±X pp」= 换个种子重跑，同一手牌的全下频率最多动的百分点数（对照表
`strategy-8bb.seed3.json`）。

跨种子表现：

| 求解设置 | 跨种子平均 \|ΔP\| | 最大单点抖动 |
| --- | --- | --- |
| 调和平均 150 轮 | 1.85 pp | 18.7 pp |
| 调和平均 600 轮 | 1.02 pp | 10.8 pp |
| 线性平均 600 轮（发货） | 1.17 pp | 10.5 pp |

最差的局面固定是 **BB 面对 UTG+BTN+SB 三家全下**（≥8pp 时页面会显式警告）：
这个局面要求前面三个人都全下才到达（约 0.9% 的发牌），样本最少，均衡本身在
跟与不跟之间来回摆，平均值必然发糊。其余 13 个局面的单手牌抖动都在 9pp 以内。

## 已知偏差

除了求解器 `allin-nash.ts` 头部写的近似（每类只取一个组合、公共牌条件化）之外，
这一层还有两条要注意：

1. **这不是查表就能照抄的答案。** 均衡里对手的全下范围，是建立在「你会按这份表跟注」
   之上的。你实际对手推得比 GTO 宽或紧，这份表的跟注范围就该跟着改。
2. **位置只有四种，且假设等筹码。** 6 人桌 / 9 人桌、有人短码或深码，都不在这份表里。

## 文件

| 文件 | 作用 |
| --- | --- |
| `index.html` | **产物**：单文件网页，双击即用，策略表内嵌其中 |
| `page.template.html` | 页面源码（`__STRATEGY_JSON__` 是策略表的占位符） |
| `build.js` | 把策略表灌进模板、算数值稳定性、产出 `index.html` |
| `selftest.js` | 用 DOM 打桩跑 `index.html` 的逻辑，42 项断言 |
| `strategy-8bb.json` | 发货用的策略表（种子 1） |
| `strategy-8bb.seed3.json` | 对照表（种子 3），只用于算数值稳定性 |
